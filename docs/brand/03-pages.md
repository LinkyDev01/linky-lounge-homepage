# 03 · 페이지 정의 — 도메인과 페이지마다 무슨 일을 하는가

> 정본: 도메인 역할표 `lib/site.ts` · 주소 규율 `docs/url-policy.md` · rewrite/301 `middleware.ts` ·
> 섹션 순서 `CLAUDE.md` §2. 이 문서는 **역할과 내용물**을 적는다 — 주소 문법은 url-policy 가 정본이다.

## 1. 도메인 역할

| 도메인 | 역할 | 색인 | 트리 |
|---|---|---|---|
| **lazy-club.com** | 레이지클럽 본진. 회원 로그인·마이페이지가 사는 곳 | index | `app/(main)/lazyclub/**` 가 도메인 루트(미들웨어 rewrite). 루트 `/` 는 랜딩 인트로 |
| **lazyday-bookclub.com** | 레이지데이 북클럽 랜딩 + 신청·인터뷰·결제 | index | `app/(main)/lazyday/**`. `/lazyclub/*` 도 열리지만 noindex(운영자 검토용) |
| **admin.lazy-club.com** | 관리 화면 전용(`/admin/*`). 손님 도메인의 `/admin*` 은 여기로 307, 관리 트리 밖은 404 | 금지 | 내부 `/lazyday/admin/*` rewrite. 로그인 = 카카오·구글 + `ADMIN_EMAILS` |
| **linkylounge.com** | 링키라운지(공간) 사이트 | index | 별도 트리. **지시 없이 수정 금지** |
| vercel.app 프리뷰 | 브랜치 검토용 — `/admin/*`·`/lazyday/admin/*` 둘 다 열린다 | noindex | 공유는 `_vercel_share` 토큰, 배포 단위 ~23h 만료 |

같은 Supabase·같은 계정을 두 손님 도메인이 읽는다. 로그인 쿠키만 도메인별(eTLD+1 이 달라 한 번 더 로그인).

## 4. 관리 (admin.lazy-club.com/admin)

`AdminShell` 좌 내비 6: **홈**(요약 숫자·손볼 것·최근 활동) · **고객**(`/admin/customers[/키]` — 사람 단위 파생 뷰,
활동 기록 메모·통화·문자) · **접수**(`/admin/applications` — 원장 조회, 상태 정본은 시트) · **주문** · **일정**(차단 달력
`/admin/schedule`) · **도구**(상태 점검 `/admin/status`·흐름 테스트 `/admin/simulate`). 디자인은 §9 — 라운드 0·
유채색 0, 상태는 채움·해칭·글자로. 분류(triage)는 열람 표시일 뿐 파기가 아니고, 진행 상태(status)는 시트가 정본(P5 전).

## 5. 페이지에 공통으로 적용되는 것

- **첫 방문 인트로**는 레이지클럽 도메인 진입 1회. 랜딩·하위 페이지가 이중 재생하지 않는다.
- **유입 출처**(`?src=`)는 localStorage + 쿠키에 저장, 인터뷰 페이지에서는 재캡처하지 않는다.
- **퍼널 계측** InitiateCheckout → Lead → CompleteRegistration (Meta 픽셀 + CAPI 미러, `funnel_events`).
- **실패는 감추지 않는다**: GAS 가 거절하면 손님에게도 실패 화면 + 카카오톡 제출 구제. 원장 기록이 먼저, 응답이 나중.
- **개인정보**: 접수 본문은 기수 종료(또는 접수)+1년 파기, 마케팅 동의자의 이름·전화만 철회 시까지.
  새 개인정보 컬럼은 파기 함수 2종과 같은 PR 에서.
- **새 페이지를 만들 때**: 슬러그는 운영자 확정 → url-policy §1 → robots(noindex 필요 여부) → 인트로·유휴 오버레이 노출
  여부 → §9 토큰 자체 선언(기존 .module.css import 금지) → 3뷰포트 스크린샷 → DECISIONS.
