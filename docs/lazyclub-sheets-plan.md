## 1. 현재 구조 (실사 결과)

| 항목 | 현재 |
|---|---|
| GAS 정본 | `gas/linkyincdev-main.gs` (main 병합 시 자동 배포) |
| 시트 바인딩 | **`SHEET_ID` 단 하나** — 북클럽 시트(`1yDy7…`) 고정, `ss()` 가 전역 사용 |
| 원데이 접수 | `handleOnedayApply` → `'1회성 모임'` 탭 (같은 문서 안 별도 탭) |
| 프론트 → GAS | `/api/lazyday/apply` → `INTERVIEW_GAS_URL` 프록시 |
| 원데이 payload | `type:"oneday"` + name/gender/age/phone/greeting/instagram/**meetingDates**/orderId/marketingConsent/consentAt |

**칼럼 뭉침의 원인**: 프론트가 제목·회차·일시를 **하나의 문자열**로 합쳐 `meetingDates`
한 필드에 보낸다(`MeetingApplyForm.tsx`). GAS 는 그걸 '모임 일자' 한 칸에 그대로 적는다.
→ **분해는 시트가 아니라 payload 구조화가 선행**이다.

## 2. 목표 구조

```
레이지클럽 신청 관리 (신규 스프레드시트, 별도 파일)
├─ 커피앤바            ← 신규
├─ 원데이 토크          ← 북클럽 시트에서 이전
└─ (모임 늘면 탭 추가)
```

- GAS 는 `SHEET_ID`(북클럽) 옆에 **`LAZYCLUB_SHEET_ID`** 를 두고, 레이지클럽 계열
  핸들러만 그쪽을 본다. 기존 북클럽 핸들러는 **한 줄도 건드리지 않는다.**
- 탭 이름은 모임 단위. 모임이 늘면 **payload 의 slug 로 탭을 자동 생성**(`ensureSheet`)
  — 모임 추가할 때마다 GAS 를 고치지 않아도 되게.

## 3. 실행 순서 (§6 절차 — GAS 먼저, 프론트 나중) — **완료 2026-08-25**

**A. 커피앤바 페이지** ✔ `app/(main)/lazyclub/meetings/dm-gd/`
- **정적 세그먼트**로 신설 — `[slug]` 동적 라우트보다 우선하므로 ONE_DAY_MEETINGS 에
  넣지 않아도 되고, 그래서 모임 목록·일정·카트·검색에 새지 않는다.
- 운영자 참가폼 이미지(800×2000)를 **웹 조판으로 재현** — 솔뫼김대건체 서브셋(26KB,
  `scripts/gen_solmoe_subset.py` 재생성). 색은 원본 실측(주황 #f49c3c · 플럼 #845c64 ·
  세이지 #94ac9c). 카피는 운영자 원문 그대로.
- 우상단 원형 로고 **10초 반시계 회전** (실측 -90°/2.5s), `prefers-reduced-motion` 정지.
  ⚠ 셸 내비 로고는 같은 10초 **시계** 방향이다 — 의도된 대칭.
- 첫 문장은 **좌측 등속 티커**(운영자 2026-08-25, 레퍼런스 outstanding-co.kr 상단 바의
  반대 방향) — 실측 59px/s, 4벌 순환. 문구도 "안녕하세요. 동민과 고든입니다."로 교체.
- 신청 폼 5필드 — 희망 날짜와 시간대는 **직접 타이핑**(운영자 결정 4).
- 사람 소개의 네비올로·네그로니 링크 목적지 교체 ✔ (people-config 한 곳 → 소비자 2곳
  자동 반영: `/people/[slug]` · 모임 상세 PersonIntro)

**B. 레이지클럽 시트 신설 + GAS 라우팅** ✔ (#490 병합, **v32 로 실배포됨** 2026-08-25)
- `LAZYCLUB_SHEET_ID` 스크립트 속성 + `lazyclubSs()`/`lazyclubSheet(탭)`
- `handleCoffeeBar` (`type:"coffeebar"`) → '커피앤바' 탭, 관리자 메일만
- ⚠ 시트 파일은 **첫 접수 때 GAS 가 만든다** — 만들면 운영자에게 링크를 메일로 보내고
  ID 를 스크립트 속성에 적어 둔다. 미리 만든 파일을 쓰려면 그 속성에 ID 를 넣으면 된다.

**C. 원데이 토크 이전 + 칼럼 분해** ✔
- 프론트 payload 를 항목별로 분해: `meetingTitle`·`meetingSlug`·`meetingDate`·
  `meetingSessions`. **`meetingDates` 는 당분간 함께 보낸다**(구 GAS 폴백 대비).
- 실측 전송값(비로소 4주 과정): 모임=제목 / slug=not-squeezing-myself /
  일시="10.3–10.24 (매주 토) 오전 10:00–12:00" / 회차="1주차 … 4주차 …"
- 남은 정리: 실제 접수 1건으로 시트 칸을 눈으로 확인한 뒤 `meetingDates` 와
  GAS 쪽 폴백을 같이 걷어낸다.

## 4. 위험과 대비

- ⚠ **뒤집힘 유실**: 이번에는 지켰다 — GAS(v32) 배포를 확인한 뒤 프론트를 병합했다(§6).
  앞으로 payload 계약을 바꿀 때도 같은 순서.
- ⚠ **기존 접수 흐름 무중단**: 북클럽 핸들러·`SHEET_ID` 불변. 레이지클럽은 새 상수로만.
- ⚠ **과거 데이터**: 북클럽 시트의 기존 '1회성 모임' 행은 **옮기지 않고 그대로 둔다**
  (이전은 신규 접수부터). 필요하면 별도 지시로 수동 이관.
- ⚠ **커피앤바는 결제가 없다** — 선신청 후 개별 연락 구조(카피 근거). 결제 여정과 무관.
