# 모임장 모집 페이지 + 레이지데이 북클럽 모임 페이지(원형) 기획 v2 (2026-09-03)

> **상태: 제안(진행중).** 운영자 지시 "위 모임장 구인 페이지를 참고하여 우리도 모임장 구인 페이지를 만들거야.
> 레이지클럽 홈페이지를 만들거고, 레이지클럽의 철학을 기반으로 레이지데이 북클럽의 모임페이지를 기획해줘".
> **v2 정정(운영자 "레이지클럽 역시 모임장이 직접 가져오는 구조야")**: v1 은 레이지클럽이 책, 발제문, 주제를 준비하고
> 모임장은 진행만 맡는 구조로 잘못 놓았다. **레이지클럽은 모임장이 자기 모임(주제, 작품, 형식)을 직접 가져오는 구조**이고,
> 레이지데이 북클럽은 그 구조 안에서 운영자가 직접 여는 **원형 모임**이다. v1 의 '레이지데이가 준비하는 것' 섹션과
> 지원서 설계는 폐기하고 아래로 대체한다. 레포의 방향과도 맞는다 — `one-day-config.host` "플랫폼화(다수 모임장) 대비 필드",
> 개편 결정 "플랫폼화(다수 모임장) 확장 구조로 공인"(01-decisions 2026-08-04), `WorkroomHome` "외부 모임장이 생기면 그 모임장명이 뜨도록".
>
> 레퍼런스 3곳: 트레바리 파트너 모집(블로그), 동행클럽 모임장 모집(host.donghaeng.club), 동행클럽 지원 폼(paperform).
> 정본 우선순위는 `CLAUDE.md` > `docs/DECISIONS.md` > `docs/brand/*`. 화면에 들어갈 브랜드 카피는 여기서 만들지 않는다.
> §5 와 §6 의 '카피 출처' 열이 슬롯마다 원고를 누가 채우는지 밝힌다. **§10 의 결정 항목이 확정되기 전에는 구현에 들어가지 않는다.**

## 0. 결론

두 페이지를 한 묶음으로 기획한다. 모집 페이지가 "모임장이 되면 당신의 모임이 이렇게 생긴다"를 보여 주려면 **모임 페이지의 원형**이 먼저 있어야 하고, 그 원형이 레이지데이 북클럽이다.

|---|---|---|---|
| 모임장이 가져오는 것 | 책과 주제, 지역 | 키워드(영화, 와인, 요리 등 8 카테고리), 3시간 진행 계획 | **작품과 화두**(문학, 철학, 예술의 한가운데), 형식(원데이 토크, 4주 과정, 기수제), 회차 계획 |

동행클럽의 '모집 중 주제 목록'(8 카테고리, 수십 개 모임)은 우리에게 없다. 대신 **형식 3종**(원데이 토크, 4주 과정, 기수제)과 **원형 모임 1개**(북클럽)를 보여 준다. 카테고리 대신 형식으로 묻는 이유는 우리 모임의 정체가 주제가 아니라 대화의 문법(발제, 자기소개 규칙, 불협화음)에 있기 때문이다.

## 2. 레이지클럽 철학이 모집 페이지에서 하는 일

- **한 문장**: "저마다 다른 삶의 궤적 속 불협화음이 예술의 본질을 관통하여 하나의 선율이 되는 순간을 소망합니다." 모임장 각자의 삶의 궤적이 곧 모임이다. 모집 페이지의 리드는 이 문장의 자리를 그대로 잇는다(북클럽 문장 '사유, 고전' 교차 복사 금지).
- **결(아비투스)**: 모임장을 고르는 기준이 이력이 아니라 결이다. 지원서가 이력서가 아닌 이유(§6).
- **불균형의 균형**: 모임장들의 세계가 서로 다를수록 레이지클럽의 목록이 산다. 단, 각 모임 안에서는 "고개만 끄덕이는 느슨한 공감의 자리가 아닙니다"가 지켜져야 한다. 모임장이 가져오는 모임의 조건이 이것이다. 주제는 자유, 문법은 공유.
- **선별은 초대의 절차**: 멤버가 인터뷰를 지나듯 모임장도 대화를 지난다(§8).
- **절제 = 자신감**: 혜택 나열 대신 원형 모임 페이지 하나를 보여 준다. 홈은 인덱스이므로 모집은 홈 히어로가 아니라 링크 한 줄이다.

## 3. 자리 (도메인, 주소, 진입점, 색인)

### 3-1. 도메인: lazy-club.com

모임장은 한 기수보다 오래 남는 관계다(09-02: 장기 관리 단위는 레이지클럽 기준). 모임장이 가져오는 모임이 원데이 토크, 4주 과정, 기수제 어느 형식이든 한 페이지에서 받는다. 북클럽 랜딩 안의 섹션은 기각 — 랜딩은 기수 모집 서사 한 편이라 CTA 소유권이 갈린다(05 반면교사).

### 3-2. 주소 (운영자 확정 필요, url-policy §1)

| 자원 | 후보 | 판단 |
|---|---|---|
| 모집 페이지 | **`/hosts`** (추천) | `/mypage` 선례처럼 내비에 없는 독립 화면. 섹션 슬러그가 전부 복수형이라 단수 `/host` 는 어긋난다. `/people/host` 는 개인 핸들 네임스페이스 침범, `/meetings/host` 는 모임 슬러그 충돌로 기각 |
| 지원서 | **`/hosts/apply`** | 모임 신청서 `/meetings/[slug]/apply` 와 같은 깊이. noindex |
| 북클럽 모임 페이지 | **`/meetings/lazyday-bookclub`** (추천) | 모임 슬러그 규칙(케밥 영단어). 기수가 바뀌어도 슬러그는 그대로(슬러그는 주민번호). 대안 `/meetings/bookclub-4` 는 기수마다 주소가 늘고 301 원장이 쌓인다 |

북클럽 도메인에서는 `/lazyclub/hosts`, `/lazyclub/meetings/lazyday-bookclub` 으로도 열린다. 관리 호스트에서는 404.

### 3-3. 진입점 (홈은 인덱스, 발명형 히어로 금지)

| 후보 | 판단 |
|---|---|
| **사람 페이지(`/people`) 맨 아래 한 줄 + 푸터 링크** (추천) | 사람 = 진행자 페이지라 맥락이 맞다. 내비 6개와 슬러그 체계를 흔들지 않는다. 밑줄 텍스트 + ↗ |
| 모임 목록(`/meetings`) 맨 아래 한 줄 | "이 목록에 당신의 모임을" 자리. 추천안과 **병행** |
| 홈 리스트 notice 항목 | 모집 기간에만. 홈 '신청' 단어 금지 규칙이라 제목은 사실 서술형(운영자 원고) |
| 내비 2행 | 내비 항목은 운영자 확정 6개. 상시 항목이 아닌 모집은 넣지 않는다 |

### 3-4. 색인

`/hosts` 와 `/meetings/lazyday-bookclub` 은 index + sitemap. `/hosts/apply` 는 noindex(`robots.ts` disallow, `/mypage` 와 같은 처리). OG 는 레이지클럽 브랜드 문장.

## 4. 디자인 체계와 시안

레이지클럽 트리이므로 `docs/redesign/02-design-tokens.md`, `08-workroom-transplant.md`, CLAUDE.md §9 가 정본. 북클럽 §3 팔레트는 쓰지 않는다. 신규 CSS 는 기존 `.module.css` 를 import 하지 않고 토큰을 자체 선언한다(`meeting-apply.module.css` 선례). 검증 390 / 768 / 1280. 시안은 `/lazyday/preview/lazyclub-hosts` 에 실셸(`Shell`) 안으로 실배치하고 스위처로 전환한다.
