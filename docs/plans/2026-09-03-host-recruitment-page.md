## 1. 레퍼런스 실측 요약과 우리의 차이

세 페이지를 curl 로 받아 본문을 추출했다(2026-09-03). 구조만 차용하고 문구, 이미지, 메뉴명은 복제하지 않는다(01 §5).

| | 트레바리 파트너 모집 | 동행클럽 모임장 모집 | 동행클럽 지원 폼 |
|---|---|---|---|

| 말투 | 해요체, 이모지(📚 🔻 1️⃣), 감탄 | 해요체, 이모지(🙌 🔥), "프로 진행러" | 해요체, ":)" |
| 우리가 가져오는 것 | 골격 순서(무엇을 하는가 → 누구를 기다리는가 → 절차 → 문답 → 사람), FAQ 의 "완벽해야 하는 사람이 아닙니다" 같은 **불안 해소형 문답의 존재** | 절차를 3단으로 명시하는 것, 진행 중인 사람의 이야기로 끝맺는 것, 지원서 10분 소요 안내 | 자기소개를 한 문장으로 시작하게 하는 장치, 진행 계획을 구체적으로 묻는 것 |

세 곳 모두 **플랫폼**이다. 모임장이 주제를 가져오고 플랫폼이 모객한다. 우리는 반대다. **책, 발제문(레이지 노트), 공간, 접수, 인터뷰를 레이지데이가 준비하고 모임장은 대화의 중심을 지킨다**(`FeatureQuietSection` 원문 "호스트는 대화의 중심을 지키며 우리가 길을 잃지 않도록 부드럽게 방향을 짚어 줍니다"). 이 차이가 페이지의 뼈대다. 레퍼런스에서 가장 긴 '혜택' 섹션이 우리에겐 '레이지데이가 준비하는 것' 한 목록으로 바뀐다.

## 2. 자리 (도메인, 주소, 진입점, 색인)

### 2-1. 도메인: lazy-club.com

- 근거 ①: 09-02 원칙. 회원, 인증, 관리처럼 오래 남는 것의 이름과 도메인은 레이지클럽 기준. 모임장은 한 기수보다 오래 남는 관계다.
- 근거 ②: 북클럽 도메인에 두면 원데이 토크, 4주 과정의 진행자를 구할 때 페이지를 또 만들어야 한다. 레이지클럽에 두면 "지금 모집하는 프로그램" 한 줄만 바뀐다.
- 근거 ③: 운영자 지시가 "레이지클럽 홈페이지를 만들거고"로 시작한다.
- 대안(기각): 북클럽 랜딩 안의 섹션. 랜딩은 기수 모집 서사 한 편이라(03 §3) 모집 대상이 다른 섹션이 끼면 CTA 소유권이 갈린다(05 반면교사 "페이지 직무 혼합, CTA 소유권 침범").

### 2-2. 주소: `/hosts` 와 `/hosts/apply` (운영자 확정 필요, url-policy §1)

| 후보 | 판단 |
|---|---|
| **`/hosts`** (추천) | 섹션 슬러그 규칙(내비 라벨 영문 대응)의 예외가 아니다. `/mypage` 선례처럼 내비에 없는 독립 화면은 라벨 자체가 없다. 소문자 영단어, 케밥 규칙 충족 |
| `/people/host` | `people/[slug]` 는 **개인 핸들** 네임스페이스다. 'host' 라는 핸들을 영영 못 쓰게 되고, 사람 목록에 섞인다. 기각 |
| `/meetings/host` | 모임 슬러그 네임스페이스와 충돌. 기각 |
| `/host` (단수) | 가능하지만 섹션 슬러그가 전부 복수형(`meetings`, `products`, `people`)이라 어긋난다 |

북클럽 도메인에서는 `/lazyclub/hosts` 로도 열린다(다른 레이지클럽 페이지와 같은 미들웨어 규칙). 관리 호스트에서는 404.

### 2-3. 진입점 (홈은 인덱스, 발명형 히어로 금지)

| 후보 | 판단 |
|---|---|
| **사람 페이지(`/people`) 맨 아래 한 줄 + 푸터 링크** (추천) | 사람 = 진행자 페이지라 맥락이 맞는다. 내비 6개와 슬러그 체계를 흔들지 않는다. 링크 문법은 밑줄 텍스트 + ↗ |
| 내비 2행 우측('레이지데이 북클럽' 옆) | 내비 항목은 운영자 확정 6개다(02 §4 헤더 2행). 상시 항목이 아닌 모집을 내비에 두면 모집이 끝났을 때 자리가 빈다 |
| 홈 리스트 항목(notice 문법) | 모집 기간에만 홈 리스트 첫 항목으로. 2-3 추천안과 **병행 가능**. 단 홈에 "신청" 단어 금지 규칙이 있으니 항목 제목은 사실 서술형("5기 모임장을 찾습니다"류는 운영자 원고) |
| 북클럽 랜딩 푸터 링크 | 북클럽 도메인에서 레이지클럽으로 나가는 링크는 새 탭 규칙. 2차 |

### 2-4. 색인

- **index + sitemap 등재** 추천. 모집 페이지는 검색 유입이 목적이다. 레퍼런스 두 곳 모두 공개 색인이다.
- `/hosts/apply` 는 noindex (폼 페이지. `/mypage` 와 같은 처리, `robots.ts` disallow).
- OG 는 레이지클럽 브랜드 문장 그대로("저마다 다른 삶의 궤적 속 불협화음이 예술의 본질을 관통하여 하나의 선율이 되는 순간을 소망합니다."). 세 자매 문장 교차 복사 금지. 페이지 제목은 운영자 확정.

## 3. 디자인 체계와 시안 3종

레이지클럽 트리이므로 `docs/redesign/02-design-tokens.md`, `08-workroom-transplant.md`, CLAUDE.md §9 가 정본이다.
북클럽 §3 팔레트(주황, 오트 A/B 교차)는 쓰지 않는다. 신규 CSS 는 기존 `.module.css` 를 import 하지 않고 토큰을 자체 선언한다(`meeting-apply.module.css` 선례). 검증 뷰포트 390 / 768 / 1280.

**시안은 `/lazyday/preview/lazyclub-hosts` 에 실셸(`Shell`) 안으로 실배치하고 스위처로 전환한다.** 가짜 밴드 쇼케이스는 금지(IntroRuleLab 교훈).

| 시안 | 골격 | 근거 | 우려 |
|---|---|---|---|
| **A. 모임 상세 문법** (추천) | 상단 15열 그리드: 좌 포스터(1/8, 데스크톱 sticky) + 우 요약(11/15, `.infoRows` 문법으로 프로그램, 기간, 요일, 장소, 회차) → 전폭 괘선 → 중앙 460px 본문 컬럼(§4 섹션들) | 워크룸 원본을 실측해 옮긴 **이미 있는 문법**이다(`ProductDetail` + `centerBody`, DECISIONS 08-19). 모집을 '하나의 모임'처럼 다루면 요약 열이 사실 정보를 맡고 본문이 원고를 맡아 역할이 갈린다. 포스터 자리에 4기 포스터(800×1000)를 그대로 쓸 수 있다 | 요약 열에 가격, 구매하기, 카트가 없는 상세라 `ProductDetail` 을 그대로 쓰면 빈 행이 남는다. 상세 컴포넌트를 재사용하지 말고 같은 클래스 값으로 전용 페이지를 짠다 |
| B. 사람 페이지 문법 | 상단에 `HostIntro`(안동민, 천고든 카드) → 괘선 문답 리스트 → 지원 링크 | "모임장이 어떤 사람인가"를 사람으로 먼저 보여준다. 레퍼런스의 '모임장 이야기'를 앞으로 당긴 구조 | 두 사람의 약력이 자기 풍자체라 모집 페이지 첫 화면으로는 톤이 튄다. 원고가 카드 아래에 오면 위계가 뒤집힌다 |
| C. 한 단 폼 페이지 | `max-width 460px` 한 단. 리드 원고 → 절차 3단 → 문답 → 같은 페이지 아래에 지원서 | 동행클럽 paperform 처럼 페이지와 폼이 하나라 이탈이 적다. 폼 문법(`meeting-apply.module.css`)을 그대로 쓴다 | 이미지가 없어 백지 위 글만 남는다. 지원서가 페이지에 붙으면 noindex 분리(2-4)가 안 된다 |

시안 공통: 이모지 0, 색면 버튼 0, 숫자 카운터 0, 마감 임박 연출 0. 모션은 셸 공통(인트로, 유휴 오버레이) 외 추가 없음. 상태 표기가 필요하면(모집 중, 마감) 글자 라벨로.

## 4. 페이지 구성 (시안 A 기준. B, C 는 같은 슬롯을 다른 골격에 배치)

카피 출처 열의 뜻: **원고 재사용** = 이미 레포에 있는 운영자 원문을 그대로 인용(강조 마크업만) / **운영자 작성** = 새 원고가 필요하며 AI 가 쓰지 않는다 / **사실 표기** = 컨피그 파생값.

| # | 슬롯 | 역할 | 내용 요건 | 카피 출처 |
|---|---|---|---|---|
| 0 | 셸 | 헤더 2행, 푸터 | 레이지클럽 공통 | 셸 |
| 1 | 라벨 + 제목 | 이 페이지가 무엇인지 한 줄 | 라벨은 13.2px "모임장". 제목은 **범주로 정의하지 않고 장면으로**("~하는 독서모임 모임장 모집" 금지, 09-03 원칙). 합쇼체 평서 | 운영자 작성 |

## 5. 지원서 (`/hosts/apply`)

**서식**: 레이지클럽 폼 문법(`MeetingApplyForm` + `meeting-apply.module.css` 값 사본. 460px 한 단, 잉크 괘선, 입력칸 16px 이상, 제출 버튼만 `.actionBtn` 잉크 채움). 제출 중 전면 로더(`TurtleLoader`), 실패 시 입력값 유지 + 원문 복사 + 카카오톡 채널 구제. 완료 화면은 "순차 확인 후 연락" 사실 서술(즉시 접수 약속 금지).

**원칙**: 주소, 이메일 미수집(주소 미수집 원칙. 결과 안내는 전화와 카카오톡). 글자 수 강제 없음. 필수는 이름, 전화, 자기소개, 지원 이유, 동의뿐.
