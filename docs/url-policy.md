# 레이지클럽 URL 정책 (2026-08-23 제정)

> 운영자 지시 "그 규칙을 설계하여 명시화해줘" — 2026-08-21~22 URL 라운드(섹션 슬러그
> 확정 → 사람 슬러그 3단 변경)에서 몸으로 배운 규율을 문서로 못 박는다.
> **적용 범위: 레이지클럽 트리(lazy-club.com / `app/(main)/lazyclub/**`).**
> 북클럽(lazyday) 트리는 종전 관례 유지 — 이 문서가 소급 적용되지 않는다.

## 0. 방식의 선택 (왜 이렇게 하는가)

자사몰 URL 관리는 크게 세 갈래다: ① 숫자 ID(`/products/12345` — 카페24·무신사류),
② 영문 슬러그(`/products/coffee-mug` — Shopify 핸들, 브랜드 자사몰 표준),
③ ID+슬러그 하이브리드(`/dp/B0XXXXX` — 아마존류, ID 가 신원·슬러그는 장식).

**레이지클럽은 ②를 쓴다.** 품목 수가 적어 하이브리드는 주소만 길어지고, 숫자 ID 는
링크가 아무 말도 하지 않는다(+ 숫자 전용 슬러그는 §4 의 기술 결함도 있다).
②의 대가는 "이름이 바뀌면 주소가 바뀐다"는 것 — Shopify 는 이걸 자동 리다이렉트로
막아 주는데, 우리는 그 장치를 §3 의 원장으로 손수 유지한다. 이 문서의 존재 이유다.

## 1. 주소의 문법

```
lazy-club.com/<섹션>/<슬러그>
```

| 자원 | 섹션 | 슬러그 규칙 | 예 |
|---|---|---|---|
| 섹션(목록) | — | **내비 라벨의 영문 대응어** (2026-08-21 확정) | `all` `meetings` `products` `people` `schedule` `records` |
| 모임 | `meetings` | 작품·과정을 나타내는 영단어(케밥) | `brahms` `not-squeezing-myself` |
| 제품 | `products` | 품목명 영문(케밥) | `coffee-mug` `printed-t-shirt` |
| 사람 | `people` | **개인 핸들** (운영자 부여) | `dmahn` `gdcheon` |

- 소문자 `a–z`·숫자·하이픈만. 공백·한글·대문자·언더스코어 금지.
- **숫자로만 된 슬러그 금지** (§4).
- 새 슬러그는 운영자 확정 후에만 — 임의로 짓지 않는다(사람 핸들은 특히).
- **관리 화면은 `admin.lazy-club.com/admin/*`** (2026-09-02) — 운영자 전용, 이 슬러그 규칙 밖, 색인 안 함. 손님 도메인의 `/admin*` 은 그리로 307.

## 2. 불변 원칙 — 슬러그는 이름표가 아니라 주민번호다

**한 번 공개된 슬러그는 바꾸지 않는 것이 기본값이다.**
화면에 보이는 이름(상품명·모임명·사람 이름)이 바뀌어도 슬러그는 그대로 둔다.
'티셔츠'가 리뉴얼되어도 `printed-t-shirt` 는 유지 — 주소를 저장·공유한 사람,
인스타 링크인바이오, 검색엔진 색인이 전부 그 주소에 걸려 있다.

같은 이유로 **폐기된 슬러그의 재사용·재배정 금지.** `andongmin` 을 다른 사람에게
주는 순간, 공유된 주소가 다른 사람을 가리킨다.

## 3. 부득이한 개명 — 301 원장

바꿔야만 한다면(운영자 지시) 절차는 하나다:

1. 데이터 파일의 slug 교체 + **역참조 소비자 전수 grep** (`hostSlug`,
   `CURRENT_SEASON_HOSTS`, `PersonIntro` 등 — 하나라도 빠지면 화면이 **에러 없이
   조용히 빈다**, 2026-08-22 실측).
2. `middleware.ts` 의 원장에 `구슬러그: "새슬러그"` 한 줄 추가:
   - 섹션: `LAZYCLUB_RENAMED`
   - 사람: `LAZYCLUB_PEOPLE_RENAMED`
   - (모임·제품 개명이 처음 생기면 같은 문법으로 표를 신설)
3. 검증: 구 주소 301 + **쿼리스트링(utm·fbclid) 보존** + 두 도메인
   (lazy-club.com 루트 경로 / 북클럽 도메인 `/lazyclub/*`) 모두.

**원장은 append-only 다 — 청소하지 않는다.** 한 줄씩 늘어나는 게 정상이고,
지우는 순간 그 주소를 저장해 둔 사람이 404 를 본다. 중간 단계로 잠깐만 나갔던
슬러그도 남긴다(순번 8자리가 하루도 안 나갔지만 원장에 있다 — 그 사이 집어간
링크가 있을 수 있다).

## 4. 금지 사항 (실측 근거 포함)

- **숫자 전용 슬러그** (`00000001`): Next 의 dev 타입 검증기가 잘못된 식별자를
  생성해 `npx tsc --noEmit` 가 깨진다(프로덕션 빌드는 통과해 잠복한다 —
  2026-08-22 실측). 기술적으로도, 링크 가독성으로도 손해.
- **rewrite 로 두 주소를 다 살리기**: 같은 문서가 두 주소로 열리면 색인이 갈라진다.
  구 주소는 반드시 301 (rewrite 아님).
- **원장 없이 slug 만 교체**: 공유된 링크가 전부 404 가 된다.
