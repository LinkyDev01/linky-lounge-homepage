# 포스터 실 경로 — 원본 PDF 파서

`POSTER_THREAD_D`(app/(main)/lazyday/poster-thread.ts)의 **출처**. 4기 포스터를 만든
미리캔버스 원본을 PDF 로 내보내면 안이 벡터라 **글자 하나하나의 아웃라인과 배치 행렬**이
들어 있다. 잉크를 추적하거나 호를 추정할 필요 없이 좌표를 그대로 읽으면 된다.

## 순서

```
python3 pdfglyphs.py     # PDF → 글리프 367개 (좌표·회전·bbox)   → /tmp/pdfglyphs.pkl
python3 assign.py        # Form XObject 17개 ↔ 본문 17줄 배정     → /tmp/assign.pkl
python3 buildpath.py     # 읽기 순서로 글자 중심 잇기 + 공백 보간 → /tmp/pdfpts.npy
python3 emit2_pdf.py     # 주기 스플라인 → 베지어 방출·검증       → /tmp/pdfpath.txt
```

`pdfglyphs.py` 상단의 PDF 경로만 바꿔 주면 된다.

## 좌표 변환

- 페이지 810 × 1012.5 pt = 캔버스 **1080 × 1350 px** (× 0.75)
- 콘텐츠 오프셋 `1 0 0 1 14.419115 91.895749 cm`
- `viewBox = 설계px × 400/1080`, y 는 `500 − y`

## 배정이 맞는지 보는 법

- 폼별 글리프 수의 다중집합이 17줄의 **비공백 글자 수**와 정확히 일치해야 한다
- 배정 후 각 줄 끝 → 다음 줄 시작이 **6~11u**(공백 한 칸 + 글자 한 칸)로 이어지고,
  17줄 끝이 1줄 시작과 **7.3u** 로 닫혀야 한다
- 큰 글자 12자(Form 16~27)를 `POSTER_GLYPHS` 와 대조하면 **평균 0.5u** 안에 든다

## 이음매 규율 — 경로가 반복 피치보다 길어야 한다

크롬은 글리프가 경로 끝에서 **1.44u 안쪽**에 들어와야 그린다(가시 구간 = L − 1.443,
글자 무관 상수). 그래서 `피치 == L` 로 맞추면 두 벌의 가시 구간 사이에 1.4u 구멍이
생겨 글자가 이음매를 지날 때마다 0.14초씩 사라진다. **L = 피치 + 2.0u** 로 두어
구멍 대신 미세 중첩을 만든다. SMIL 이동량은 **통짜 텍스트로 잰 피치**를 쓸 것
(tspan 으로 재면 경계 반올림 때문에 다르다).

합격 기준

| 항목 | 기준 | 왜 |
|---|---|---|

| `drawn` | **474** (한 벌 전부) | 폴백 서체로 본문이 길어지면 뒤쪽이 경로 밖으로 밀려 안 그려진다 |

⚠ **재개 대기시간을 `performance.now()` 로 재지 말 것.** 내비게이션 기준이라 번들 로드가
느리면 "진입이 끝났다"고 오판해 12% 에서 통짜로 넘어간다. CSS 애니의 `currentTime` 을 쓰되
**마지막 글자**의 애니여야 한다 — 첫 글자는 지연 0·길이 0.2s 라 200ms 에서 멈춘다.

### ⚠ 정지에는 반드시 무조건 실행되는 재개 경로를

진입을 정지시켜 두고 재개를 계산 뒤에 두면, **계산이 실패하는 브라우저에서 본문이
영원히 안 보인다.** 실제로 웹킷(iOS·사파리)은 `<text>` 의 글이 `<textPath>` 안에
있으면 `getComputedTextLength()` 가 **0** 이라 이 사고가 났다.

지금 코드는 3겹으로 막는다 — ① 재개가 계산보다 **먼저** ② 3초 안전핀 타이머
③ 폭 측정 3단계 폴백(`<text>` → `<textPath>` → 화면 밖 평문 프로브 `data-probe`).
프로브로 쟀을 때는 이음매 여유를 2.0u → 6.0u 로 넓힌다(프로브 값이 경로 배치 폭과
0.4% 어긋나 여유를 먹을 수 있다).

세 단계를 각각 재현해서 확인할 것:

```js
// Playwright addInitScript — <text> 만 0 / textPath 까지 0
SVGTextContentElement.prototype.getComputedTextLength = function () {
  if (this.tagName === "text" && this.querySelector("textPath")) return 0
  if (MODE === "probe" && this.tagName === "textPath") return 0
  return orig.call(this)
}
```

셋 다 `--lz-play` 가 **running**, 여유가 **1.44u 초과**, 렌더 자수가 한 벌 전부여야 한다.

## 이음매 δ — 구멍과 중첩은 같은 결함의 양쪽 (2026-08-14 10차)

크롬은 글리프가 경로 양 끝 여백 안에 들어와야 그린다. 그 여백의 합을 **2m**(실측
**1.46u**) 이라 하면 가시 구간은 `L − 2m`, 그러니 보이는 글자 수가 위상과 무관하게
일정하려면 **반복 피치 P = L − 2m** 이어야 한다.

```
δ = (L − 2m) − P
δ < 0  구멍   이음매에서 글자가 사라진다
δ > 0  중첩   같은 글자가 양 끝에 동시에 그려져 겹쳐 찍힌다
δ = 0  무이음 사라지는 글자와 나타나는 글자가 늘 같은 글자 → 화면상 아무 일도 없다
```

9차의 "여유를 넉넉히 2.04u" 는 **틀렸다**. δ = +0.583u 라 글자가 이음매를 지날
때마다 58ms 씩 겹쳐 보였다 — 주기 0.77초, 약 **1.3Hz 의 깜빡임**.

```bash
node scripts/poster-pdf/seam-delta.mjs      # δ · 한 주기 전수 검사 min/max
python3 scripts/poster-pdf/rescale.py <목표L> <현재L>   # 경로를 그만큼 스케일
```

합격: `δ ≈ 0` **그리고** `min = max = 355`.
⚠ "누락 프레임 0" 만 보면 중첩(356)을 놓친다 — 9차가 그렇게 통과했다.

⚠ **맞추는 쪽은 언제나 경로 길이다.** 크롬은 font-size 를 1/64px 로 양자화하므로
474자 기준 한 칸이 7.4u — 런타임 크기 보정으로 0.6u 를 맞추는 건 원리적으로 불가능하다
(무효이거나 7.4u 를 통째로 넘긴다). `textLength` 도 크롬은 textPath 에서 무시한다(실측).

### 이음매는 **런타임 자동 보정**이다 (2026-08-14 11차)

10차에서 경로를 오프라인으로 0.583u 줄여 크롬 δ 를 0 으로 맞췄지만, 운영자는
여전히 "시작/종료 이어지는 부분에서 글자가 한 자씩 사라져" 를 보고했다. 이유:

> **피치 P 는 엔진마다 다르다.** 같은 서체·같은 7.2px 라도 advance 를 다르게 눌러
> 담는다. 크롬 기준으로 맞춘 경로는 다른 엔진에서 δ ≠ 0 이 된다.

CSS 로는 P 를 못 고친다 — font-size·letter-spacing·word-spacing 이 **전부 1/64px 로
양자화**돼 474자 기준 최소 조정 폭이 5~7u 다(실측). `textLength` 는 크롬이 textPath
에서 무시한다(실측). **남은 유일한 연속 손잡이가 경로 길이**이고, 그건 `d` 를 다시
써서 런타임에 바꿀 수 있다 (`scalePosterThreadD`).

`HeroBreathingPoster.tuneSeam()` 이 하는 일:
1. 화면에 없는 **2벌짜리 사본**(`text[data-seam]`)으로 δ 를 이분 탐색(20회 × 2)
2. 경로를 `(L − δ) / L` 배 스케일 → δ 가 정확히 0 이 된다(모델이 정확해 1회면 충분,
   이분 탐색 잔차만 2회차로 턴다)
3. **그어짐을 재개하기 전에** 끝낸다 — `d` 재작성은 한 프레임을 0.2초까지 늘리므로
   (실측 187ms) 아직 아무것도 안 움직이는 정지 상태에서 치러야 티가 안 난다

```bash
node scripts/poster-pdf/seam-engine-sim.mjs 0.02em    # 자간으로 다른 엔진 흉내
```
자간 −0.02em ~ +0.02em(피치 −78u ~ +53u)에서 전부 δ ≤ 0.008 · min = max = 355 로 수렴.

⚠ 그러니 **앞으로 서체를 바꿔도 poster-thread.ts 의 `d` 를 다시 재지 않아도 된다.**
파일의 값은 크롬 기준 출발점일 뿐이고 나머지는 런타임이 맞춘다.
⚠ 숨은 사본 두 개(`data-probe`·`data-seam`)는 **보이는 본문 뒤**에 둔다 —
앞에 두면 `querySelector('textPath')` 가 사본을 집어 검사 도구가 엉뚱한 걸 잰다.

### 엄격 검토 라운드에서 추가된 규율 (2026-08-14)

1. **검증은 반드시 보이는 본문(`textPath[data-stream]`)으로.** 숨은 측정 사본으로
   검증하면 크기 보정이 사본에 안 미쳐 거짓 통과가 난다 — 실제로 한 번 났다.
   도구: `strict1`(scratchpad) — 기본/±0.02em/웹킷 흉내 4조건에서
   δ ≤ 0.002 · min=max · SMIL 이동량 = 실측 피치.
2. **보정 순서는 "크기 → 경로".** fitToPath(거친 손잡이, 폴백 구제)가 tuneSeam
   (고운 손잡이, 이음매) 뒤에 오면 방금 맞춘 이음매를 크기 변경이 부순다.
   fitToPath 의 목표 길이는 반드시 **살아 있는** `getTotalLength()`.
3. **램프는 깨끗한 프레임에서 발화.** 통짜 교체 + 강제 리플로우가 흐름 시작 프레임을
   0.4초까지 늘린다(실측 395ms) — 같은 블록에서 beginElement 하면 가속 300ms 가
   멈춘 화면 안에서 소모돼 "가속이 없어 보인다". 더블 rAF 뒤에 발화한다.
   검증: `ramp.mjs` 로 초반 속도가 0 부터 올라오는지 (0 → 0.27 → … → 10 u/s).
4. **내비·푸터 시계는 포스터가 준다.** 셸의 벽시계 타이머만 믿으면 서체 대기 중
   그어짐 8% 에 내비가 뜬다. 포스터가 재개 시점에 `lz:hero-draw-start` 로 남은
   시간을 알리고, 이벤트가 없으면 셸 타이머가 종전대로 동작(의존 아님).
   검증: `strict2` — 콜드/웜 모두 내비 시점의 그어짐 99%, CTA +3.0초.
5. **측정 전 `.next/BUILD_ID` 시각 확인.** 서버가 낡은 번들을 서빙하면 전 항목이
   거짓 실패로 보인다(실제 소동). `pkill` 은 자기 명령줄을 물어 자살하므로(§5)
   포트 기준 `fuser -k 3100/tcp` 로 죽일 것.

### 진입 = 마스크 스윕 (2026-08-14 최종)

글자별 스태거는 폐기됐다 — 글자가 이산적이라 프레임이 밀리면 여러 자가 한꺼번에 떠
"딱딱" 끊기는 원리적 한계(운영자 "이전처럼 한 줄로 쭉"). 지금은 경로 사본의 굵은
획(16u)에 dashoffset 스윕을 걸어 마스크로 드러낸다 — 시안 ① 선 긋기 그대로.
본문은 SSR 부터 통짜 REPEAT(4)벌: 흐름 시작의 교체·재배치 히치(395ms)와 교체 순간
자간 갈림이 함께 사라졌다 (프레임 최장 25.5ms).

```bash
node scripts/poster-pdf/sweep-check.mjs 1600   # 인자 = 폰트 지연 ms
```
합격: 100ms 구간별 이동 127u 고정 · 정지 없음 · 프레임 최대 점프 ≤ 22u.
⚠ reduced-motion 에서 `animation: none` 만 쓰면 dashoffset 2800 에 멈춰 본문이
영영 안 보인다 — `stroke-dashoffset: 0` 을 반드시 함께. CSS 2.2s = TSX DRAW_MS 동기.
